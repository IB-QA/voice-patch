### The joke, photographed

`~/.voicemode/voicemode.env` has:

```text
VOICEMODE_KOKORO_PORT=8090
VOICEMODE_TTS_BASE_URLS=http://127.0.0.1:8090/v1
```

`voicemode status` / `voicemode service start|restart kokoro` read that
value (`KOKORO_PORT` in `config.py`, used in `tools/service.py`).

The process that actually binds the port does **not**.
`~/.voicemode/services/kokoro/start-gpu_mac.sh` is the upstream clone
script. Last line as shipped:

```bash
uv run --no-sync uvicorn api.src.main:app --host 0.0.0.0 --port 8880
```

It never sources `voicemode.env`. Contrast mlx-audio's plist, which
does `set -a; . "$HOME/.voicemode/voicemode.env"`, and Whisper's
generated start script, which uses `"$WHISPER_PORT"`.

First start therefore:

1. `service start kokoro` → `⚠️ Kokoro loaded but not yet listening on port 8090`
2. uvicorn log → `Uvicorn running on http://0.0.0.0:8880`

Install-time rewrite exists but does not close the gap:

- `voicemode kokoro install --port` **defaults to 8880** in `cli.py:807`,
  ignoring `VOICEMODE_KOKORO_PORT`.
- `tools/kokoro/install.py` only rewrites `--port 8880` when `port != 8880`,
  and then writes a **copy** `start-custom-{port}.sh`. Launchd still
  starts `start-gpu_mac.sh` via `get_service_config_vars`.
- So a custom CLI port can produce a unused custom script while the
  plist still binds 8880.

## MLX Audio install and role audit (08:36)

### What the service actually is

VoiceMode installs upstream **mlx-audio 0.4.3** as a uv tool and launches its
actual `mlx_audio.server` entry point. This is not a VoiceMode clone-only
wrapper and it is not an `mlx-lm` server.

The installed FastAPI application exposes:

- `POST /v1/audio/speech` — TTS; request must name a model.
- `POST /v1/audio/transcriptions` — STT; request must name a model.
- `GET/POST/DELETE /v1/models` — in-memory loaded-model registry.
- realtime transcription WebSocket and audio-separation routes.

Models load lazily from the request's Hugging Face model ID. Current cache
evidence on this machine includes:

```text
mlx-community/Kokoro-82M-bf16
mlx-community/whisper-large-v3-turbo-asr-fp16
mlx-community/whisper-tiny
```

Misaki is required by the MLX Kokoro implementation for text-to-phoneme
conversion. `mlx-lm` is a direct upstream dependency of mlx-audio and is used
inside Qwen-family and other transformer TTS architectures. Their presence
does not mean the server is only for voice cloning.

### Misleading UI message

The upstream root route always returns:

```text
Welcome to the MLX Audio API server! Visit https://localhost:3000 for the UI.
```

The UI is only started when `mlx_audio.server --start-ui` is supplied.
VoiceMode correctly does **not** pass that flag. Therefore no UI on port
3000 is expected; the unconditional root message is an upstream UX bug.

### Port behavior

The VoiceMode launchd template sources `~/.voicemode/voicemode.env` and then
uses `VOICEMODE_MLX_AUDIO_PORT`, falling back to 8890. Unlike Kokoro, the
runtime plumbing is correct. On this machine the env file has
`VOICEMODE_MLX_AUDIO_BASE_URL=http://127.0.0.1:8890/v1` but **does not define
`VOICEMODE_MLX_AUDIO_PORT`**, so binding to 8890 is the documented fallback,
not yet proof that a configured port was ignored.

However, `voicemode service install mlx-audio` exposes no `--port` and calls
`mlx_audio_install()` with its hardcoded default 8890. The Python installer
temporarily sets the env variable only for rendering/enabling; it does not
persist a chosen port into `voicemode.env`. This still violates the desired
single-source configuration contract.

### Why the normal installer combines services

The current `install.sh` does not install Whisper, Kokoro, and MLX Audio all
at once on Apple Silicon:

1. Recommended `mlx` choice = **whisper.cpp for STT + mlx-audio for TTS**.
2. `local` choice = **whisper.cpp for STT + kokoro-fastapi for TTS**.
3. If MLX Audio installation fails, Kokoro is installed as TTS fallback.

The stated reason for keeping whisper.cpp load-bearing is VM-1421 / VM-94:
the MLX Whisper path has a repetition bug. This creates a product-contract
contradiction: help describes MLX Audio as unified STT+TTS, while the
recommended installer deliberately uses only its TTS.

No recommendation to remove whisper.cpp can be made until the repetition bug
is reproduced against the currently installed 0.4.3. Likewise, no claim that
MLX Kokoro is faster or more stable than kokoro-fastapi can be made from
source inspection; that requires the same utterance/model/format benchmark.

### Uninstall and fallback gap

The code contains `mlx_audio_uninstall`, including launchd, uv-tool, optional
model-cache, and log cleanup. But the unified `voicemode service` CLI has
**no uninstall command**. Deprecated Whisper help tells users to run
`voicemode service uninstall whisper`, a command that does not exist.
Kokoro and Whisper uninstall remain stranded under deprecated groups; MLX
uninstall has no discoverable CLI route.

Provider runtime has ordered endpoint failover, but installation/uninstallation
does not atomically reconcile endpoint lists. Removing a backend can leave
`TTS_BASE_URLS` or `STT_BASE_URLS` pointing at a dead first endpoint, adding
avoidable connection-failure latency before fallback. Clean removal therefore
requires both service cleanup and provider-list repair.
